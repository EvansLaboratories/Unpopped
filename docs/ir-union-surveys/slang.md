## 2. Ten highest-impact gaps (ordered by measured corpus effect, then breadth)

1. No `Let`/mutable locals/structured control flow (Loop, If, break, early exit). It is the connective blocker in slang-second-blocker-sizing.md and gates every non-trivial kernel and autodiff. Add SSA-with-regions or structured Let/Loop/If (ir.rs:63 is a single expression).
2. No groupshared/workgroup memory + per-thread identity (ThreadIdx/BlockIdx/LaneId). 36 of 147 Fuel files. Add `SharedAlloc`, `SharedLoad/Store`, thread/block id leaves, `LaunchShape`.
3. No barriers (execution and memory, per scope). Needed by every cooperative kernel. Add `Barrier{scope,exec,mem}`.
4. Atomics are only a scatter combine (Add/Max/Min, int max/min). Missing CompareExchange (16 files), Exchange, And/Or/Xor, fetch-old result, MemoryOrder, scope, float min/max, 64-bit, on shared memory. Add value-producing `AtomicRmw/AtomicCas`.
5. Subgroup/wave ops entirely absent (reduce, prefix, shuffle, ballot, match, clustered, quad). Add `Subgroup*` node family plus `SubgroupSize/LaneId`.
6. Cooperative matrix and cooperative vector: no tile/fragment value type, no MMA node; AccumSpec has only `WideFloat`. Add `TileTy`, `TileLoad/Store/Fill/Mma/Convert/Reduce/Map`, `VecTile` + `MatVecMulAdd/OuterProductAccumulate`, and the MMA AccumSpec variants (TF32, F16, Bf16, Int8, Fp8, Int4, B1).
7. Raw/pointer memory: no byte-offset typed load/store (RWByteAddressBuffer, 1 Fuel file), no pointers/buffer device address, no struct/array/vector/matrix value types. Add `Ptr`, `RawLoad/Store`, `Bitcast`, aggregate types.
8. Numerics controls absent as IR fields: fp-mode (fast/precise), denorm modes, fma as a fused node, rounding modes, NaN/Inf preservation. Today they are emitter side-channels (`required_slangc_args`). Add `NumericsMode` on OpDef and `Fma`.
9. Textures/samplers/images and bindless handles (`DescriptorHandle`, `ResourceDescriptorHeap`, `nonuniform`). Zero IR representation. Add `Image` operand kind + `Sample/Fetch/ImageStore`, `Handle<T>`.
10. Autodiff (`fwd_diff/bwd_diff`, custom derivatives, `DifferentialPair`) and specialization (spec constants, link-time constants/types). Autodiff needs gap 1 first. Add `Transform::Fwd/Bwd`, `SpecConst`, `ExternConst`.

Runners-up: integer bit ops (popcount/clz/bitfield), multi-result intrinsics (sincos/frexp/modf), function calls, Slang dtype spellings for F16/Bf16/Fp8 in the emitter, `spirv_asm`/target-intrinsic escape, parameter blocks/push constants.

## 3. Things in the IR / in-tree Slang emitter that look wrong or risky relative to Slang

1. Stale policy in docs, not code: `docs/groupshared-sizing.md` and `docs/idiom-lifting-design.md` section 1a say "the IR never models cooperation". The owner has overruled that; both should be superseded, and `convert.rs` `SLANG_RESIDUE` (groupshared/barriers/atomics refused as "residue") is now a gap list, not policy.
2. Finite constants are spelled with `{v:?}` unsuffixed (backend.rs:1027 `const_lit`, reused by Slang). In HLSL/Slang an unsuffixed floating literal is `float` (UNVERIFIED for Slang specifically; no primary page fetched). If true, an F64 kernel's constants (e.g. 0.1, and the Log10 factor `0.4342944819032518` at lib.rs:~486) are truncated to f32 before widening, silently losing f64 precision. Check a pre/post with `slangc -target spirv` on an f64 `Const(0.1)` body; the in-tree test at lib.rs:~920 only checks `double` buffer types. Slang spelling to use: `double(...)` cast or an `L`/`lf` suffix (suffix spelling UNVERIFIED).
3. `UnaryOp::Sign` at lib.rs:~471 spells `x > 0 ? 1 : (x < 0 ? -1 : 0)`: NaN yields 0.0, whereas the same file comments elsewhere that torch semantics are the target and torch.sign(NaN)=NaN (torch behavior from memory, UNVERIFIED here). Also `Expm1` as `exp(x)-1.0` and `Log1p` as `log(1.0+x)` lose precision for small |x| (a precision-contract question, not a compile error); Slang's own `expm1`/`log1p` availability UNVERIFIED (not found in the pages fetched).
4. `UnaryOp::Round` comment says "HLSL round = round-half-to-even (matches rintf)" (lib.rs:~473). That is true of HLSL (round_ne) but Slang targeting SPIR-V may lower `round` to GLSL.std.450 `Round` whose tie direction is implementation-defined, with `RoundEven`/`rint` separate. The stdlib index lists both `round` and `rint` (REF global-decls). UNVERIFIED which opcode Slang emits; safer spelling is `rint(x)` for the half-even contract. Needs a SPIR-V disassembly check.
5. `Relu` spelled `x < 0.0 ? 0.0 : x`: for F64 the literals are float (see 2) but exact here; for f16 would be a half/float mixed expr. Low risk.
6. Selection and capability model: `unpopped-slang` gates 8/16-bit ints by a "vulkan:sg32.arith-..." target string and declines F16/Bf16 outright (lib.rs:133, 299). Slang has first-class `float16_t`, `BFloat16`, `FloatE4M3`, `FloatE5M2` types (REF types index), so the decline is an emitter gap, not a Slang limit. For CUDA-via-Slang, Slang says pointers/flat memory are supported (UG targets.html), so int8 gating by a Vulkan-style capability string may not transfer to the `cuda`/`metal`/`wgsl` targets.
7. `is_integer_kind` (ir.rs:~2240) lists I32/I64/U8/I8 only: it omits I16/U16/U32/U64, so `WriteCombine::is_fp_atomic_add` classifies a U32/U64 scatter-add as floating-point (non-deterministic variant) and routes it to the FP-atomic path. The doc comment says the `_` arm is "conservative", but for unsigned dtypes it mislabels exact integer atomics as non-deterministic. (Wrong-by-classification, not wrong math.) Also SPIR-V 64-bit atomics need the `spvInt64Atomics` capability (UG capabilities.html), which the IR cannot express.
8. Emitter reach: unpopped-slang lowers only `Schedule::Scalar` elementwise; every other schedule (Reduction, RowReduce, Contraction, Scan, Strided) is a `LowerError::UnsupportedSchedule`. So "Slang as an emit target" covers one Access variant; the corpus 0/147 acceptance is dominated by parse-side limits, but even with them fixed the emitter could not round-trip cooperative kernels.
9. `Shr`/`Shl` spelled raw `>>`/`<<` for I32/I64 (lib.rs:~590). Shift counts >= bit width are undefined/masked differently across HLSL/SPIR-V/CUDA/Metal; the IR gives no defined semantic (UNVERIFIED for Slang specifically). A per-target-divergent result here would be invisible to single-target tests.
