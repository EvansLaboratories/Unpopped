kind: added: `unpopped-cpu-c` spells a static `AllocDecl::layout`; a layout (static or `dyn_layout`) on a `Private` allocation
---
**cpu-c spells the static T1 allocation layout** (and its swizzle), as it spells a `dyn_layout`: the physical offset is C arithmetic over constants (colexicographic coordinates over the flattened shape times the strides, then the swizzle's XOR on the element offset), with no launch check because `check_kernel` already proved the layout injective and inside the extent. An `align_bytes` is accepted only with a swizzled layout (the serial C places no memory); an alignment on its own, and a layout in a kernel that would bypass it (a callee, a Device barrier, a peer access, several devices, `Mma`/`MatrixLoad`/`MatrixStore`), are still declined by name. `kernel_alloc_layout_declines` flips to accepted-with-control; new `kernel_alloc_layout_emit_agrees` (the C against the oracle, two layouts, plain and swizzled; mutants: each offset term zeroed, the swizzle XOR turned into an OR). **A layout on a `Private` allocation** (`docs/design-dynamic-layout.md` section 9): `check_kernel` accepts `layout` and `dyn_layout` on `Private` as well as `Shared` (a `Private` array is one per thread, so the layout aliases nothing); a swizzle on `Private` is refused by name ("a Private array has no banks"); `Global` stays refused (`AllocSpace`: a global array is a buffer parameter with its own shape and strides); `Constant`, `Tensor` and `Tile` are refused with a message naming the accepted spaces. cpu-c spells `sh<i>[t * extent + offset]`; `kernel_private_layout_emit_agrees` (oracle against a Rust reference across a barrier, the C against the oracle, the dynamic launch refusal as status 4, mutants: a zeroed offset term, the per-thread slice dropped). Patent: the same conditions as the dynamic-swizzle ruling (pm-kernels 2026-11-28, findings not advice, not a clearance, outside as read): XOR-bit data only, no lookup table, no map object, no emitted copy: an offset function only; the swizzle on `Private` is refused. Additive; `unpopped-cpu-c` and `check_kernel`.
