kind: docs: a layout on an allocation passed to a callee: what already holds, the cpu-c ABI design
---
`docs/design-dynamic-layout.md` section 10 and `tests/kernel_module_layout.rs`: the oracle already applies an allocation's layout (static or the launch-bound `dyn_layout`) to a callee's accesses through `CallArg::Alloc` (measured by a fill-through-a-callee read-back over a non-identity layout, static and dynamic, and a refused bind trapping before the call), so the IR needs no change; the gap is cpu-c's affine `(ptr, shape, stride, base)` buffer ABI, which the design closes with layout parameters (a C struct of integers and XOR-bit constants, not a tensor descriptor) beside only those callee parameters that receive a laid-out allocation. Design only for the emitter; the refusals that stay are listed; patent conditions as for the swizzle ruling.
