kind: added: a layout (static or `dyn_layout`) on a `Private` allocation
---
`check_kernel` accepts `AllocDecl::layout` and `dyn_layout` on a `Private` allocation as well as a `Shared` one (`docs/design-dynamic-layout.md` section 9): a `Private` array is one per thread, so the layout maps a thread's own index to its own physical element and aliases nothing. A swizzle on a `Private` array is refused by name ("a shared-memory bank pattern: a Private array has no banks"); `Global` stays refused (`AllocSpace`: a global array is a buffer parameter with its own run-time shape and strides), and `Constant`, `Tensor` and `Tile` are refused with a message that names the accepted spaces. The oracle needs no change; `unpopped-cpu-c` spells it as `sh<i>[t * extent + offset]`. Tests: `kernel_private_layout_emit_agrees` (oracle against a Rust reference across a barrier, the C against the oracle, the dynamic layout's launch refusal as status 4, mutants: a zeroed offset term, the per-thread slice dropped). Patent: the same conditions as the dynamic-swizzle ruling (pm-kernels 2026-11-28, findings not advice, not a clearance, outside as read); this row adds no hardware and no statement and refuses the swizzle on `Private`. Additive.
