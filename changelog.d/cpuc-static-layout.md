kind: added: `unpopped-cpu-c` spells a static `AllocDecl::layout` (and its swizzle)
---
The serial C emitter spells the static T1 allocation layout, as it now spells a `dyn_layout`: the physical offset is C arithmetic over constants (colexicographic coordinates over the flattened shape times the strides, then the swizzle's XOR on the element offset), with no launch check because `check_kernel` has already proved the layout injective and inside the extent. An `align_bytes` is accepted only with a swizzled layout (the serial C places no memory); an alignment on its own, and a layout in a kernel that would bypass it (a callee, a Device barrier, a peer access, several devices, `Mma`/`MatrixLoad`/`MatrixStore`), are still declined by name. `kernel_alloc_layout_declines` flips to accepted-with-control; new `kernel_alloc_layout_emit_agrees`: the C against the oracle for two layouts, plain and swizzled, with mutants (each offset term zeroed, the swizzle XOR turned into an OR) changing the bytes. Patent: the same conditions as the dynamic swizzle ruling (pm-kernels 2026-11-28, findings not advice, not a clearance, outside as read): XOR-bit data only, no lookup table, no map object, an offset function only. `unpopped-cpu-c` only; additive.
