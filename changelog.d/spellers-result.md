kind: **BREAKING**: `cfamily::unary_f32` / `unary_f64` return `Result<String, SpellError>`
---
`unpopped::cfamily::unary_f32` and `unary_f64` return `Result<String, SpellError>` instead of a `String`: they used to panic on `Popc`, `Clz` and `Brev` (integer bit operations the typing gate refuses on a float first) and now return the new `non_exhaustive` `SpellError::IntegerBitOp(op)`; every other operation spells exactly as before. `unpopped-cpu-c` maps the error to `Decline::UnsupportedDtypeForOp`. Migration: `?` or `.map_err` into the emitter's own declined-op path at each call (see `docs/emitter-migration-b1.md`); callers measured: baracuda-cuda-emit (2 delegating calls, 28 wrapper sites) and bonefish-sycl-emit (2 calls). `binary_f32`, `binary_f64` and `binary_int` still panic and are unchanged.
